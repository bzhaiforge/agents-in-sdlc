エージェントモードの GitHub Copilot は、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を受け入れたり取り消したりできます。また、エディターを離れずに追加のプロンプトを送り、作業を調整したり広げたりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- セッションの途中でエージェントに指示を送り、高コントラストモードに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティのカスタムエージェントが、高コントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者向けに、ライトモードの切り替えも追加します。新しい会話を最初から始める代わりに、現在のセッションに追加の指示を送ります。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが調べたファイル、実行したコマンド、提案した編集などの各手順を確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - 変更を受け入れるには **Keep** を選択します。
   - 変更を元に戻し、エージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイルの全体を確認できます。

> [!NOTE]
> ツールの呼び出し (ターミナルコマンドの実行など) に許可が必要な場合、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントが高コントラストモードの実装を終えるまで待ちます。完了すると、変更内容をまとめた最終メッセージが表示されます。

## ライトモードを追加するようエージェントに依頼する

高コントラストモードができたので、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けると、エージェントは前の作業、変更したコンポーネント、スタイルの方針、local storage を使った設定の保持方法を引き継ぎます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが前の変更を確認し、ライトモードの追加を提案する様子を確認します。
3. 高コントラストモードのときと同じように、新しい編集を1つずつレビューし、各差分で **Keep** または **Undo** を選択します。
4. エージェントが意図と異なる方向に進んだ場合 (たとえば、好みと異なる方法で切り替え UI をリファクタリングしようとした場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、補足の指示を送ります。

> [!TIP]
> 進行中のセッションに追加の指示を送ると、最初からやり直すよりも早く調整できます。追加のプロンプトで変更を依頼できます。たとえば、「Cascading Style Sheets (CSS) を簡潔にして、セレクターの重複ではなく CSS 変数を使う」「3つ目の切り替えを追加せず、既存の設定パネルにライトモードを追加する」「両方の切り替えにキーボードショートカットも追加する」などです。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更したファイル全体を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが指示したアクセシビリティのパターン (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティックな HyperText Markup Language (HTML)、local storage による設定の保持など) が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、方向付けました。ファイルの編集ごとにレビューし、変更を受け入れるか取り消し、コンテキストを保ったまま追加プロンプトを送って作業を広げました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れたり、取り消したりしました。
- 追加プロンプトを送り、セッションの途中で作業を調整しました。
